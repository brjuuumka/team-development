# План проверок ядра (спринты 2 и 3)

Тестовые данные синтетические: [`issued-document.json`](../examples/issued-document.json) и [`valid-chain.json`](../examples/valid-chain.json). Цепочка содержит genesis и один блок с записью. Хэши фиксированы для повторяемого примера; реальные документы в проект не добавлять.

| ID | Действие | Ожидаемый результат | Требование |
|---|---|---|---|
| T-01 | Импортировать `valid-chain.json` | Цепочка принята; 2 блока, 1 запись; результат `validate_chain()["valid"]` равен `True` | CORE-03, CORE-08 |
| T-02 | Экспортировать и импортировать цепочку повторно | Поля и хэши сохранены; импортированная цепочка валидна | CORE-08 |
| T-03 | Поменять порядок ключей JSON | Хэши не меняются, цепочка валидна | CORE-02 |
| T-04 | Изменить поле записи, оставив старые хэши | `RECORD_HASH_MISMATCH`, блок 1, возвращён `record_id` | CORE-11, CORE-12 |
| T-05 | Изменить `previous_hash` блока 1 и пересчитать его собственный хэш | `PREVIOUS_HASH_MISMATCH`, блок 1 | CORE-12 |
| T-06 | Изменить поле genesis и пересчитать его хэш | `INVALID_GENESIS`, блок 0 | CORE-03, CORE-12 |
| T-07 | Добавить дублирующий `record_id` | `DUPLICATE_RECORD`; цепочка не меняется | CORE-06, CORE-10 |
| T-08 | Добавить пустой блок | `EMPTY_BLOCK`; цепочка не меняется | CORE-04, CORE-10 |
| T-09 | Добавить запись с недопустимым событием | `ValueError`; цепочка не меняется | CORE-01, CORE-10 |
| T-10 | Проверить получение истории известного и неизвестного рецепта | Для известного — события, для неизвестного — пустой список | CORE-07 |
| T-11 | Изменить исходный объект записи после добавления | Сохранённая запись не меняется; цепочка валидна | CORE-09 |
| T-12 | Изменить выгруженный JSON в памяти | Цепочка в памяти не меняется | CORE-09 |
| T-13 | Изменить поле записи напрямую, не обновляя `record_hash` | `RECORD_HASH_MISMATCH` с индексом блока и `record_id` | CORE-11, CORE-12 |
| T-14 | Изменить запись напрямую, затем пересчитать хэш блока | Ошибка записи всё равно обнаружена как `RECORD_HASH_MISMATCH` | CORE-11 |
| T-15 | Проверить неизменённый `issued-document.json` по пути и `record_id` | Метод возвращает `True` | CORE-13 |
| T-16 | Изменить значение в копии внешнего JSON-файла | Метод возвращает `False` | CORE-13 |
| T-17 | Передать отсутствующий или невалидный JSON-файл | Метод возвращает `False`, исключение наружу не выходит | CORE-13 |
| T-18 | Импортировать цепочку версии 1 или с повреждённым хэшем записи | Импорт отклонён; исходное состояние цепочки сохранено | CORE-08, CORE-11 |

Передача на тестирование: установить `rfc8785`, затем запустить тестовый набор командой из `README_QA.md`. QA фиксирует фактические результаты отдельно и не подгоняет ожидания тестов под реализацию.
