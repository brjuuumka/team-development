# Сценарии проверки ядра (Спринты 2 и 3)

Исходные синтетические примеры: [`issued-document.json`](../examples/issued-document.json) и [`valid-chain.json`](../examples/valid-chain.json). Они содержат один genesis-блок и один блок с событием `ISSUED`. Контрольные хеши уже вычислены. Значение `nonce` фиксировано только ради повторяемого учебного примера; при создании настоящего документа его генерируют случайно.

| ID | Действие | Ожидаемый результат | Требование |
|---|---|---|---|
| T-01 | Импортировать `valid-chain.json` | Цепочка принята, содержит два блока и одно событие | CORE-03, CORE-08 |
| T-02 | Экспортировать импортированную цепочку и импортировать повторно | Содержимое и хеши совпадают | CORE-08 |
| T-03 | Поменять порядок ключей JSON, не меняя значения | Проверка остаётся успешной | CORE-02 |
| T-04 | Изменить `prescription_id` в записи блока 1, оставив старый хеш | Валидатор не падает, а возвращает `HASH_MISMATCH` с точным указанием индекса блока 1 | CORE-05, CORE-12 |
| T-05 | Изменить `previous_hash` блока 1, оставив собственный хеш | Валидатор возвращает `PREVIOUS_HASH_MISMATCH` с точным указанием индекса блока 1 | CORE-05, CORE-12 |
| T-06 | Изменить поле genesis и пересчитать только его хеш | `INVALID_GENESIS` / ошибка локализована на нулевом блоке | CORE-03, CORE-12 |
| T-07 | Добавить запись с уже встречавшимся `record_id` | `DUPLICATE_RECORD`; длина цепочки прежняя | CORE-06, CORE-10 |
| T-08 | Передать пустой список записей для нового блока | `EMPTY_BLOCK`; длина цепочки прежняя | CORE-04, CORE-10 |
| T-09 | Передать список, где одна из записей некорректна | Не добавлена ни одна запись; длина цепочки прежняя | CORE-01, CORE-10 |
| T-10 | Запросить историю известного и неизвестного `prescription_id` | Для известного возвращено одно событие; для неизвестного пустой список | CORE-07 |
| T-11 | Изменить исходный объект записи после добавления блока | Содержимое сохранённого блока не меняется (защита ссылок) | CORE-09 |
| T-12 | Изменить экспортированный объект, не добавляя его назад | Содержимое внутренней цепочки не меняется | CORE-09 |
| T-13 | Изменить данные записи в обход методов (напрямую в памяти) | Валидатор пересчитывает хэш записи и возвращает `INVALID_RECORD` с указанием поврежденного блока | CORE-11, CORE-12 |
| T-14 | Передать нетронутый внешний документ в `verify_external_document` | Ядро канонизирует документ, успешно сверяет хэш и возвращает `True` | CORE-13 |
| T-15 | Изменить поле внешнего документа и передать в `verify_external_document` | Ядро выявляет несовпадение пересчитанного хэша с эталонным в цепочке и возвращает `False` | CORE-13 |

T-01–T-12 проверяют базовую структуру и логику (Спринт 2). T-13–T-15 обеспечивают глубокую проверку на неизменяемость и соответствие реальных внешних документов (Спринт 3).
