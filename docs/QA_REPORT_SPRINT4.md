# QA-отчёт по 4 спринту

## 1. Цель тестирования

Проверить работоспособность распределённой блокчейн-системы, состоящей из нескольких независимых нод, которые могут взаимодействовать по сети и обмениваться блоками.

Основное внимание уделено корректности передачи данных, проверке целостности блокчейна и обработке ошибочных ситуаций.

## 2. Объект тестирования

Тестировались следующие компоненты:

- `src/core.py` — основная логика блокчейна.
- `src/node.py` — взаимодействие нод по сети.
- HTTP API — получение информации о нодах, создание, передача и получение блоков.
- Сохранение блокчейна в отдельные файлы.

## 3. Выполненные проверки

В рамках четвёртого спринта подготовлено и выполнено 25 автоматизированных тестов.

**Основные сценарии:**

1. Проверка независимого хранения данных двух нод.
2. Проверка идентификаторов нод.
3. Проверка одинакового начального блока (genesis).
4. Создание нового блока.
5. Передача блока между нодами.
6. Последовательная передача нескольких блоков.
7. Отклонение блока с неправильным хэшем.
8. Отклонение блока с неправильной ссылкой на предыдущий блок.
9. Обнаружение изменения данных записи.
10. Отклонение повторно полученного блока.
11. Обработка пропущенного блока.
12. Проверка несовместимой версии схемы данных.
13. Обнаружение конфликта цепочек.
14. Проверка сохранения и повторной загрузки блокчейна.
15. Проверка неизменности цепочки после отклонения блока.
16–25. Проверка HTTP API: получение состояния ноды и цепочки, создание и получение блоков, обработка некорректных запросов, взаимодействие с другой нодой и отклонение дубликатов.
