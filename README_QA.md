# Инструкция QA — спринты 3 и 4

## Область

Проверки T-01–T-18 и N-01–N-12 из [`docs/test-plan.md`](docs/test-plan.md). Для спринта 4 дополнительно проверяются две независимые ноды, HTTP-контракт, приём валидного блока, демонстрационный UI и негативные сценарии.

## Запуск

Из корня репозитория установите зависимость и запустите автотесты:

```sh
python3 -m pip install -r requirements.txt
python3 -m pytest tests/test_core.py tests/test_sprint3.py tests/test_sprint4_network.py -v
```

На Windows можно использовать `py` вместо `python3`. Зафиксируйте версию Python, `rfc8785` и `pytest`, итоговое число пройденных/непройденных тестов и текст ошибок. Не меняйте ожидаемый результат теста только для совпадения с реализацией: сначала зарегистрируйте расхождение.

## Ожидаемый интерфейс

`validate_chain()` возвращает словарь с `valid`, `error_block_index`, `error_record_id`, `reason`. `verify_external_document(path, record_id)` возвращает `True` или `False` и не выбрасывает исключение для невалидного/отсутствующего файла.

Для сети: `GET /v1/node` возвращает состояние ноды; `GET /v1/blocks/{index}` — блок; `POST /v1/blocks` принимает блок. Успех передачи — HTTP 201 и `accepted=true`; ошибка валидации — HTTP 422, `accepted=false` и машинный код в `error`.

## Статус

В локальном окружении разработки выполнена ручная smoke-проверка создания и приёма блока. Полный прогон требует установить зависимости из `requirements.txt`; фактический QA-результат должен зафиксировать тестировщик.
