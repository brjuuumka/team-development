# Правила командной работы

Основная ветка — `main`. Для одной задачи создаётся короткая ветка вида `S2-02-record`. Изменения оформляются запросом на слияние; другой участник проверяет код и соответствие критериям приёмки. После согласования ветка сливается в `main`.

В описании изменения указываются ID задачи, что изменилось, как проверено, какие ограничения остались. Для изменений формата данных обновляются примеры и версия контракта. Для программного кода обязательны проверки, соответствующие изменению.

Карточка переходит в «Готово», когда результат доступен, рецензент его проверил и замечания исправлены. Если нет доступа к общей Git-площадке, участник передаёт ветку локально менеджеру; после выбора площадки она публикуется там.

Реальные медицинские сведения, пароли и ключи не добавляются в репозиторий. Для примеров используются вымышленные данные.
